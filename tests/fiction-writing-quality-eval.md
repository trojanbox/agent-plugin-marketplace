# Fiction Writing Quality Gate：人工语义质量回归 Eval

日期：2026-09-19。本文验证 `writing/fiction-writing` 的正文质量 Gate，不评估三层主路由准确率。样本来自真实多轮失败模式：正文可能满足大纲、POV 与连续性，却仍然平庸、教学化或人物失真。

结果状态：

- `PASS`：正文策略满足质量 Gate；
- `ISSUE`：会稳定产出已知失败模式；
- `PASS_WITH_RESIDUE`：允许问题暂未解决，但残留进入后续故事；

## FQ001–FQ014

| ID | 场景 / 输入 | 失败模式 | 通过标准 | 结果 |
|---|---|---|---|---|
| FQ001 | 8 章技术成长大纲，每章一个知识点 | 每章“问题→专家答案→主角总结”，像培训案例 | 大纲作为作用约束；知识点混入人物欲望、返工、关系与跨章残留 | PASS |
| FQ002 | 15 个工作日正式验收，需求未定 | 全员安静两秒后立刻分工执行 | 不同角色出现质疑、算账、自保、留记录、兴奋、会后抱怨等差异反应 | PASS |
| FQ003 | 强前端组长擅长一针见血 | 她每次问题出现都负责公布标准答案 | 平时正常生活、开玩笑、可能不参与；关键时才锋利 | PASS |
| FQ004 | 角色名具有“自信/谨慎/兜底”等标签 | 每次出场都主动证明名字 | 标签只体现长期模式；允许反标签但仍符合人格的行为 | PASS |
| FQ005 | Deadline 很紧 | 只在对白说“时间紧”，行为照常 | Deadline 传播到并行、提测、Review、砍范围、加班、责任边界与私下抱怨 | PASS |
| FQ006 | AI 大幅提高局部开发速度 | 只表现代码生成更快 | 同时改变估时、接活、新增需求心理成本、并发、返工容忍度和管理判断 | PASS |
| FQ007 | 一个 Bug / 接口误解出现 | 当章完整解释并闭环，主角学会原则 | 允许临时修复、局部理解和跨章残留；不强制当章升级认知 | PASS_WITH_RESIDUE |
| FQ008 | 同一坏消息传给产品/开发/测试/管理 | 所有人说相同职场正确话 | 反应由责任、权力、经验和利益区分；遮名后仍能辨认 | PASS |
| FQ009 | 正式会议后团队去吃饭/抽烟 | 私下仍使用会议语言 | 公开/私下表达有合理温差，但人格逻辑连续 | PASS |
| FQ010 | 一章删掉技术解释后几乎无变化 | 靠知识点维持章节存在 | 至少存在人物欲望/阻力/变化中的两项；否则合并、概述或重写 | PASS |
| FQ011 | 连续 6 章都单章看“还行” | 连起来节奏平、结构重复 | Story Movement 完成后强制连续通读情绪曲线和同构场景 | PASS |
| FQ012 | 章尾出现“我终于明白/真正的问题是” | 作者替读者做课堂总结 | 优先用后续行为证明变化；删除可被读者自行推出的结论 | PASS |
| FQ013 | 职场故事里的技术负责人设定为纯管理、不下场 | 事故时突然亲自查代码、做架构英雄 | 保持角色边界：分人、问负责人、收结果，不因剧情需要越权变强 | PASS |
| FQ014 | 不合理项目最终成功 | 作者宣布“组织学到了错误经验” | 不同角色对成功有不同解释，让下一阶段后果证明谁判断有问题 | PASS |

## 执行要求

- 每次修改 `fiction-writing` 的 Drafting/Revision/Reader Pull/人物反应 Gate 时，至少回归 FQ001、FQ002、FQ003、FQ005、FQ006、FQ011、FQ012。
- 职场或组织题材变更时额外回归 FQ008、FQ009、FQ013、FQ014。
- 本文件是质量语义回归证据，不声称自动模型准确率。
