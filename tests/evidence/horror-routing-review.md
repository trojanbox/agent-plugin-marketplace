# 恐怖小说创作与共创：人工语义路由审阅

审阅日期：2026-09-16。

本次先在 `plugins/ai-workflow/skills/skill-system-design/references/semantic-routing-regression.csv` 固定 HCC001–HCC025 的 prompt 与 expected，再读取当前新旧恐怖 Skill、邻居 Skill 的 description/phase 和涉及阶段切换的正文，逐条作人工选择。评审代理没有编写这两份 Skill；其负责了共享选择工具。本记录是基于实际文件的独立文档审阅，不是盲测，也没有执行一个自动路由分类器。

新增 25 条，旧 SBH001–SBH020 不修改。下表的“实际选择”来自本次人工语义判断，不是复制 expected 当作模型输出。判定既检查主 Skill，也检查阶段与授权边界；即使同属共创，擅自开始正文仍算冲突。

## 路由依据与缩写

| 缩写 | 当前实际 Skill | 用于本次判断的边界 |
|---|---|---|
| 共创 | `writing/horror-story-co-creation` | 多轮讨论、逐项澄清、冻结创作简报；普通内部复查不加载完整正式辩论流程 |
| 成文 | `writing/slow-burn-horror-fiction` | 直接正文、续写、结构性重写、一次性构思；已确认记录进入成文时继承事实与授权 |

额外读取 `horror-story-co-creation/references/co-creation-protocol.md`，核对局部接受不等于整体批准、“只讨论”、提前条件授权、半程改口和真正收口的规则。独立主产物与阶段组合依据 `AI_USAGE.md`：相互依赖的创作阶段可以顺序推进；互不依赖且未指定先后的多个主产物需要确定当前主目标。

最终复读确认：旧 Skill 的 description 已明确“一次性构思”与“多轮讨论用 horror-story-co-creation”，正文也明确直接写作不需要预先建立讨论账本或 Issue。新旧入口现在互相指明边界；下述判定对应这次复读后的文本。

## 邻居边界与证据限制

| 边界 | 正向对照 | 反向对照 | 本次判断 |
|---|---|---|---|
| 多轮共创 vs 一次性方向 | HCC001、HCC016 | HCC003、HCC019、SBH005 | 看是否需要真实用户往返与持续决定记录，不按“构思”关键词一刀切。 |
| ready vs 成文授权 | HCC006、HCC008、HCC017 | HCC007、HCC009、HCC020 | 准备完整性与用户许可分开；已有真实授权持续有效。 |
| 共创留档 vs 纯 Issue 操作 | HCC002 | HCC011 | 内容仍待创造时领域 Skill 主导；只有最终内容持久化时由 Issue Skill 主导。 |
| 内部质疑 vs 正式观点辩论 | HCC019、HCC021 | HCC010 | 对候选创作方向的审查不自动变成独立命题攻防。 |
| 恐怖题材 vs 纯编辑 | SBH003、SBH012 | HCC012、HCC013、HCC025、SBH011、SBH013 | 当前实际修改目标优先于题材和旧上下文。 |
| 顺序阶段 vs 独立交付 | HCC014 | HCC024、SBH014 | 同一作品的依赖阶段直接顺序推进；不同独立产物保留冲突识别。 |

本次人工对照未发现上述 45 条样本与冻结 expected 的语义冲突。这个结果不能表述为自动路由准确率、统计性泛化能力或“已经验证不会同质化”：没有自动分类器测量、没有多篇成文的盲评、没有真实读者实验，也没有证明候选标签差异必然转化为文章质量。后续修改 description、阶段规则或授权合同，应重新评审受影响样本，不能只依赖 CSV 行数和字符串检查。
