# Slow-burn Horror Fiction / 后劲型恐怖小说

## 唯一目标

让恐怖在故事结束后继续作用于读者：通过可信日常、人物人生、具体异常、局部规律与结尾回响，使读者下一次遇见普通事物时重新想起故事。

## 最高原则与十条公理

**不要给恐怖的“神”画脸。** “神”指支配异常的终极本体、完整机制或最终解释，不限定宗教。允许鬼、伤口、尸体和强烈超自然显现；不把终极未知收束成有完整身份、动机、能力和弱点的设定表。

1. **让鬼出现，让神缺席。**
2. **让现象足够具体，让真相永远大于解释。**
3. 越靠近人，越具体；越靠近终极本体，越模糊。
4. 不宣布“不可名状”，让读者发现自己的概念不够用。
5. 恐怖要污染现实中仍会重复出现的东西。
6. 人物面对异常的方式必须从过去的人生里长出来。
7. 可以找到生存规律，但不要让规律成为宇宙真相。
8. 每一次升级都应改变前面事件的意义。
9. 真相可以增加，安全感应该减少。
10. **最好的结尾发生在文章已经结束以后。**

## 任务与输出边界

- 用户要“写故事/小说”时，直接交付正文；构思和检查在内部完成，不默认先列提纲、解释方法或附创作思路，文末不总结寓意。
- 用户要“构思”时，交付核心恐怖、人物、异常结构、升级链、Ending Echo；按所要范围展开，不提前写全文。
- 续写或结构性重写继承原文的人物经历、视角、已发生事实和用户保留项；缺少必须保留的原文时先索取，不假装已读。只缺未指定的创作细节时自行选择，不逐项盘问。
- 普通小说、纯清晰度编辑和纯去 AI 味各按自身目标处理；不因原文有鬼或日常物件就强制改恐怖结构。不扩展为通用小说框架、角色生成器或长篇项目管理。

## 核心创作闭环

1. **确定恐怖核心**：读者最终害怕什么问题？哪一个日常现实接口会把它带出故事？哪个终极问题始终不完全回答？
2. **建立正常世界**：确定地点、生活、人际关系和原本安全的信号；保留只属于普通生活、并非伏笔的细节。
3. **建立人物人生**：关键人物过去经历了什么、因此相信什么、最怕失去什么、会被哪种证据骗过、为什么采取当前行动？让欲望、愧疚、利益与价值排序参与选择。
4. **设计异常四层**：痕迹 → 显现 → 局部规律 → 保持开放的终极本体。现象可验证，显现受视角、时间、空间或认知限制；未知不等于什么都看不见。
5. **设计升级链**：新异常重新解释旧事件；保留日常恢复与解释松动的间隔，不用更大的怪物和更多血替代意义升级。
6. **设计知识代价**：每层真知识破坏哪种旧世界模型、失去哪种安全感？允许临时活下来，不保证理解越多越能控制。
7. **预设 Ending Echo**：写正文前确定最后的信息如何改写前文，以及哪个日常对象会在读者生活里再次出现；不必先定最后一句。
8. **写作**：用自然小说段落承载动作、环境、心理、对话与场景推进，让人物和事件表达主题。
9. **完稿检查**：终极本体是否被解释尽了？是否有具体显现、客观残余、人物行动依据、现实接口和双重回响？删除解释性尾巴，核对重写保留项。

## 不可妥协的写作边界

- 具体异常让恐怖成立，未知让恐怖扩大；不得把全部异常藏成哲学悬疑，也不得用“全是幻觉”抹掉客观后果。
- 人物不为剧情降智；禁忌应有损失与幸存经验，不随机堆规则；调查不收束为弱点攻略与世界彻底复原。
- 默认正常自然段。短段仅用于真正需要停顿的节点，不每一两句话换段，不用大量空白、频繁 Markdown 横线或标签化小节制造节奏；分隔应对应实际场景、时间或结构转换。
- 事实足够异常时停止解释，不追加“他终于明白”“真正可怕的是”或寒意式套话替读者反应。
- 不引用或要求模仿任何具体小说、电影、导演、作家或 IP 的风格；例子只示范方法，不把某种物件、遗忘机制或民俗道具固定成模板。

## Skill Composition / 能力组合

只有用户同时明确要求“去 AI 味 / humanize / 别像 ChatGPT”时，在恐怖结构完成后组合 `writing/humanizer`。它只处理表达，保留叙事事实、刻意的信息空缺、必要复现、自然段与结尾回响；本 Skill 保留人物、节奏和结构决策。用户只要给已完成小说去 AI 味时，由 Humanizer 主导。

## 按需读取

构思新故事、设计异常或结构性重写时，读取 [references/horror-playbook.md](references/horror-playbook.md) 的第 1–8 节；局部续写、节奏或结尾修订只读对应节。完稿审校时读取第 9–10 节的失败模式与检查表。不要把手册和内部设计表当成小说的默认输出。
