# Fiction Writing / 小说成文

## 唯一目标

在用户已经确认或明确委托的方向范围内，把作品真正写成**值得继续读的小说正文**。**拥有表达自由，不拥有未授权的方向自由。**

守住合同只是底线，不是质量完成条件。正文同时必须具备人物真实反应、场景阅读能量、情绪变化和连续生活感，不能只做到“设定没错、信息齐全、技术正确”。

## 主流程

1. **读取创作合同**：优先使用当前对话、用户给出的架构/大纲/正文、【创作】Issue 当前正文和 Story Development Plan。已经确认的内容不重问。
2. **判断授权范围**：Genre/作品身份、核心阅读体验、关键人物关系、Story Movements、终点、POV、明确禁区默认不能自行改变；对白、动作、段落、场景内部节奏、生活细节和局部描写属于表达层自由。
3. **正式成文前加载 Drafting Gate**：写完整场景、章节、续写或多章节正文前必须读取 `references/drafting.md`。短到只是一两句局部补写时可不加载。
4. **直接写模式**：用户明确“剩下你定/别问我/直接写”时，可在其授权范围内内部完成必要的轻量 Architecture + Development，再直接交正文；不展示机械问卷，不伪称模型选择是用户原话确认。
5. **先写“人”，再写“功能”**：重大刺激到来时，人物先产生符合人格、关系、社会位置和现实利益的情绪、身体反应、判断、自保或抱怨，再进入解决问题模式。不同人物面对同一刺激应允许产生不同反应；公开场合与私下表达可以有明显温差。
6. **大纲不是 Checklist**：Story Movement、章节纲和知识点描述的是戏剧作用，不是正文逐条覆盖清单。多个要点在真实生活里会混在一起时允许混在一起；问题可以跨场景、跨章节残留，不要求每章都“提出问题 → 给答案 → 学到一课”。
7. **让高影响条件真正进入行为**：如果故事依赖期限、疾病、资源匮乏、战争、规则、秘密、身份限制，或某种新工具/能力/资源显著改变人物能力边界，它必须改变人物的选择阈值、优先级、关系或日常，而不能只停留在设定或对白里。同一结果允许不同人物得出不同结论，不由作者统一宣布“正确经验”。
8. **执行作品表达合同**：保持已定调性、语言倾向、叙事距离、描写密度、对白和节奏方向。人物反应来自既有人格，不来自类型套路或作者需要。
9. **诚实 POV 与信息**：不靠作者作弊隐瞒视角人物自然知道的信息；不给视角人物提前植入后期认知；不给读者替人物总结“真正危险/终于成长/后来才明白”。
10. **保持连续性**：分章/多轮写作时检查人物位置、关系、时间、物件、已知信息和上一个自然单元的结尾，不重复回放同一事件。
11. **逐章质量 Gate**：每个完整章节/自然单元写完后，在持久化或继续下一章前快速自审。至少回答：
    - 这一章最有意思、最好笑、最紧张、最尴尬、最爽或最让人好奇的 1～2 个瞬间是什么？答不出来就重写；
    - 有没有人物只是为了让剧情继续而迅速变理性、配合或正确？
    - 同一刺激下，主要人物反应是否有差异；公开/私下反应是否符合关系和权力位置？
    - 有没有把大纲 bullet、技术知识点或“本章主题”机械演一遍？
    - 章尾相较章首，局势、关系、情绪、认知或读者期待是否至少有一项真实变化？
    - 有没有作者在章尾替读者总结“这一章学到了什么”？
    未通过时先重写当前单元，不把明显问题推迟到整本修订。
12. **Story Movement 连续通读**：一个 Story Movement、连续 3～8 章或用户定义的阶段写完后，必须从头连续读一遍再继续下一段，重点检查情绪曲线、同构场景、人物声音、关系熟化速度、教学案例化，以及外部约束或能力变化是否真的传播到人物行为。
13. **整本完稿与修订**：整本完成后再进行全局问题导向修订，最后才进入句子级精修。统计只用于诊断，不作为字数、章长或词频 KPI。

## Reader Pull / Scene Energy Gate

正文不要求每场都大冲突，但必须存在某种阅读能量。完整场景至少应能回答其中两项，关键场景最好三项以上：

- 当前谁想得到、保住、避免或证明什么？
- 什么人、规则、现实条件或人物自身阻碍了它？
- 哪件事没有按人物预期发展？
- 场景结束后什么状态改变了？
- 如果删掉这场，除了少一个知识点/信息点，人物、关系、情绪或故事是否真的有损失？

如果一场只能回答“把某个知识点讲清楚了”，它更像案例或说明文，不足以单独支撑小说场景。

## 结构性重写边界

- 只压缩冗余、改对白、调整段落、重写某场但保持原作用 → 本 Skill 直接执行。
- 会改变 Story Movement、核心人物、重要关系、作品身份、POV、时间范围、终点或主要支线 → 先使用 Architecture/Development 完成重新设计，再由本 Skill 写入正文。
- 用户明确“结构你自己定/直接给新版”时，视为相应高影响选择的委托，可内部顺序执行前两层能力后直接重写，不额外制造确认轮次。

## 按需读取

- 正式场景/章节落地、连续性、Show/Tell、人物反应和阅读能量检查时读取 `references/drafting.md`；完整章节写作默认触发。
- 单章重写、Story Movement 连续通读、整本修订、章节边界复核和停止修订时读取 `references/revision.md`。
- 当前作品需要类型知识时读取 [Genre 索引](../../shared/fiction/genres/index.md)，只加载已经与作品身份匹配的类型 reference；类型知识不得重新定义作品。
- 用户要求长期 GitHub 正文存档时读取 [创作 Issue 工作流](../../shared/fiction/references/creative-issue-workflow.md)。

## Skill Composition / 能力组合

- 用户明确要求“去 AI 味 / humanize”时，在叙事事实、人物、信息和作品合同确定后组合 `writing/humanizer`；本 Skill 保留小说事实和场景决策。
- 用户明确要求【正文】Issue/长期 GitHub 存档时组合 `github/github-issue-manager`；本 Skill 负责正文，Issue 能力只负责真实持久化。

## 停止边界

- 发现一个未授权的高影响方向必须重定 → 不在正文里偷改；回到对应前置阶段或向用户确认。
- 当前主要任务只是已有文本清晰改写/去 AI 味 → 不抢编辑类主路由。
- 用户要求暂停/只看当前稿时立即停，不为了“完整流程”继续扩写或修订。
