# Narrative Patterns for Popular Science Explainers

仅在长篇、多层机制或视频脚本任务中按需读取。

## Pattern A：工程与技术的 Constraint Ladder

适合通信、芯片、发动机、数据库、网络协议、航天、能源系统等。

```text
需求 / 日常结果
→ 最原始可行方案
→ 瓶颈 1
→ 技术 1
→ 瓶颈 2
→ 技术 2
→ 资源/物理极限
→ 更高维度的解法
→ 当前系统
```

每一层回答五件事：

1. 我们现在想解决什么？
2. 最简单办法是什么？
3. 它为什么不够？
4. 新办法利用了什么机制？
5. 它具体换来了什么，同时付出什么？

## Pattern B：自然科学的 Model Refinement Ladder

适合天文、生物、化学、地球科学、物理现象。

```text
可观察现象
→ 最简单解释模型
→ 模型做出预测
→ 出现反例/边界/新观测
→ 修正模型
→ 新模型解释更多现象
→ 仍然未知的部分
```

这里“下一层”不必是工程发明，也可以是更深的机制、尺度变化或新的理论描述。

不要把历史上实际发生的发现顺序伪装成必然逻辑。如果讲科学史，明确区分“为了教学重建的推理链”和“真实历史过程”。

## Pattern C：数学与抽象概念的 Necessity Ladder

适合概率、微积分、线性代数、信息论等。

```text
具体任务
→ 现有工具能做到什么
→ 遇到一个它处理不了的情况
→ 引入新的表示/运算
→ 用新工具解决原问题
→ 做一个反例或边界检查
→ 再抽象为正式定义
```

定义应作为压缩已有理解的工具，不作为开场障碍。

## Pattern D：发现史 / 实验叙事

```text
旧观点或未解问题
→ 关键观察/实验
→ 哪一部分不符合预期
→ 新假设
→ 验证或反驳
→ 今天如何理解
```

不要为了戏剧性制造不存在的“天才顿悟”。历史事实必须有证据。

## 认知步幅设计

每一个 beat 最好只做一种动作：

- 建立对象；
- 建立因果；
- 给一个例子；
- 暴露限制；
- 给新解法；
- 命名；
- 量化；
- 回顾。

如果一个 beat 同时要求受众记三个新名词、理解一个公式、接受一个新类比，它太大了。

## 类比复用策略

一个长解释可以有多个类比，但每个类比应有明确“管辖范围”。

示例结构：

```text
类比 1：解释基本传播/交互
    ↓ 到此停止
类比 2：解释资源分配/并行
    ↓ 延续数个概念
真实机制：指出类比无法覆盖的部分
```

不要把不同类比的对象互相混用。

## 视频脚本骨架

长视频可以先做如下蓝图，再写完整旁白：

| Beat | 观众此刻知道什么 | 新问题 | 新理解 | 视觉任务 |
|---|---|---|---|---|
| Hook | 日常经验 | 它怎么做到？ | 隐藏复杂度 | 熟悉场景 |
| Model 1 | 现象存在 | 信息/能量如何传？ | 最小机制 | 简单动画 |
| Constraint 1 | Model 1 有效 | 为什么现实不够？ | 第一个瓶颈 | 失败演示 |
| Upgrade 1 | 瓶颈明确 | 怎么绕开？ | 新机制 | 对比动画 |
| ... | ... | ... | ... | ... |
| Return | 能解释完整链条 | 这意味着什么？ | 回到日常 | 与开场呼应 |

视觉不是装饰。每一格都应承担一个认知任务。

## 结尾回环

优先：

1. 用 2–5 行压缩核心机制；
2. 回到最开始的动作/现象；
3. 给读者一个“以后再看到它时，会多看见一层”的新视角；
4. 如需情绪，只留一句。

好的结尾增强理解后的感受，不代替理解本身。
