# 科普解释的类比、术语、公式、节奏、视觉与首尾

长篇说明、视频脚本、需要类比/公式/视觉设计或最终润色时读取。

## 类比规则

类比用来搭桥，不能替代机制。

### 选择类比

优先选择受众熟悉、结构对应清楚的对象：道路、水波、声音、排队、容器、地图等。

### 保持连续

同一组概念如果可以在同一个类比世界中继续生长，优先延续它。这样读者只维护一张心智地图。

但不要为了连续强行扭曲事实。**类比连续性服从正确性。**

### 明确映射

必要时内部先写清：

```text
类比中的 A → 真实机制中的 X
类比中的 B → 真实机制中的 Y
类比解释得好的部分 → ...
类比开始失效的位置 → ...
```

避免“一会儿水管、一会儿快递员、一会儿高速公路”导致读者每分钟重建一次世界观。

## 术语与公式

### 术语

- 专业词尽量在直觉形成后出现；
- 首次出现时，用一句话说明它给哪个已理解概念命名；
- 缩写只展开一次，之后保持一致；
- 不为了显示知识量堆同义术语。

### 公式

公式出现前，读者应先知道：

- 每个量代表什么；
- 关系大概往哪个方向变化；
- 为什么此处真的需要公式。

优先顺序：**直觉 → 图/例子 → 关系 → 公式 → 用公式做一个预测。**

如果公式不能增加解释力，可以不放。

## 句子与节奏

对于视频旁白、口头讲解：

- 一句话尽量只推进一个主要逻辑台阶；
- 用短句承载结论，用中等句长解释因果；
- 复杂度通过连续多步建立，不把五层条件塞进一个长句；
- 允许“但现实中……”“这就带来另一个问题”这类自然转折，但不要机械重复同一句式；
- 反问只放在受众此刻真的会产生疑问的位置。

对于文章，可以把多个连续短句合并成自然段，保持同样的认知步幅，避免写成字幕碎片。

## 视觉与旁白分工

当任务是视频、动画、PPT 或图解科普时，不要让旁白承担所有信息。

- **视觉**适合：空间关系、运动、几何、数量变化、流程、前后对比；
- **旁白**适合：因果、问题、转折、解释和结论；
- 画面已经清楚展示的内容，旁白不要逐像素复述；
- 引入星座图、结构图、波形、时间线等视觉对象时，旁白告诉观众“该看哪里、这个变化意味着什么”。

需要长视频脚本时，可以输出双轨：`旁白 | 画面/动画意图`。

## 开头与结尾

### 开头

推荐三步：

```text
熟悉场景 / 现象
→ 隐藏复杂度或反直觉矛盾
→ 本次解释承诺
```

不要用百科定义开场，除非用户明确要辞典式回答。

### 结尾

先压缩回顾真正学到的机制，再回到开头现象。

可以有一小段有画面感的收束，但必须“挣回来”：前文已经提供足够具体事实后，才允许出现诗意或宏观表达。

不要使用没有事实支撑的宏大升华、万能“科技改变世界”或模板式励志句。

## 输出模式

根据用户任务选择一种：

- **直接解释**：直接给科普答案，隐藏方法论；
- **科普文章**：标题 + 连贯叙事正文；
- **视频解说稿**：按 narrative beats 写旁白，必要时带视觉提示；
- **Explain Blueprint**：用户要先看结构时，给“起点 / 最小模型 / 约束阶梯 / 术语出现点 / 结尾回环”。

除非用户要求，不要先展示一大堆框架再开始讲知识。

## Final Gate

交付前逐项检查：

- 第一层模型是否足够简单，同时没有关键错误？
- 每个新概念是否都解决了一个前面已经出现的问题？
- 受众在听到术语之前是否已有可挂载的直觉？
- 类比是否清楚映射，并在失效处及时停止？
- 是否把事实、解释模型和类比分清？
- 每一个数字是否来自可靠信息，并真正帮助理解？
- 是否存在“跳了三步却用一句显然带过”的逻辑断层？
- 视频任务中，视觉是否承担了适合视觉的认知负担？
- 结尾是否回到了开头，同时避免廉价升华？
- 是否在学习方法，而没有机械复制某位创作者的标志性措辞或固定表达？
