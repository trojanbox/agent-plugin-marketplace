# Fiction Prose Editing / 小说语言精修

## 唯一目标

在既有故事事实和人物行为已确定时，提升小说文字自身的**自然度、细腻度、句际连贯与节奏分寸**。允许输出 Protect / No Change；不把“句子变短、更加白话、删掉心理描写”冒充文学进步。

## 触发与邻接

- 主路由：“小说剧情别动，只把文笔打磨舒服”“这段遣词别扭”“文字太干/不细腻”“像出版小说那样自然流畅”“做一次纯文笔 A/B 精修”。
- 由 fiction-manuscript-drafting 组合：**完成正式整章初稿以后**，作为后置语言编辑阶段；不进入起稿时的逐句生成清单。
- 只问“文风有没有漂、像不像当前作品” → `writing/fiction-review` 的 Expression 模式；只问“读者是否看懂术语/因果” → `writing/fiction-review` 的 Readability 模式。
- 纯事实说明的清晰压缩或一般文章去 AI 味 → `writing/clear-writing`（Humanizer 模式）。已经写好的小说若只要求删除一般套话且没有文学质感目标，可由该通用模式主导。
- 用户要求改变主要情节、人物、POV、信息释放或章节结构时，由 fiction-discussion / fiction-manuscript-drafting 的对应 Owner 主导。本 Skill 不借润色暗改高影响内容。

## 准备与冻结

1. 读取待修正文与相邻上下文。存在 Storybook 等项目合同时，按项目 AGENTS / Book 规定完成必要 Preflight；读取当前 Style、Character Voice、已确认的正式正文样本和相关 Preserve Set。
2. 明确硬边界：事件及因果、人物知情范围、POV、时间空间、对象、关键动作、对白意图、伏笔功能、固定落点。用户要求“对白逐字保留”时必须原样保留。
3. 先圈出真正有效的词句、生活细节和情绪呼吸，作为 Protect Set。Voice Baseline 可约束作品身份，但其文字若存在已证实的缺陷，不因“它是基线”而将缺陷永久复制。

## 工作流

1. **连读诊断**：以完整自然段为单位找出实际阻力，区分词语搭配、指代/受事混乱、句际视点跳跃、感受过度抽象、动作解说化、重复确认、节奏同质化。问题必须能指出原文和阅读代价。
2. **局部精修**：先修词语与句法，再按人物注意力连接观察、身体感受与心理；必要时调整相邻句轻重及段落呼吸。允许保留长句、完整心理和真实停顿，不设固定字数/段长/感官密度。
3. **前后连读**：检查语言变化有没有把技术质感、人物口吻、有效日常、含蓄与留白一并磨掉。既有标准模式机器人的机械表达、人物故意的笨拙或不流畅应按角色需要保留。
4. **A/B 判定**：对照原稿与新稿，陈述“更自然/更细腻”的具体收益及新增代价；若仅更短、更工整或没有可证实增益，保留原稿。复杂对照可交 fiction-revision-validation 作独立验收。

详细句级方法、编辑强度和失败模式，**仅在实际要修改/评估正文时**读取 references/chinese-prose-editing.md；纯路由判断不预加载。

## 输出与写入

- 用户只要诊断时，给有证据的问题和保留项，不擅自重写。
- 用户要求精修时，交付可直接阅读的完整目标片段；解释关键改法和未解决的疑点。必要时附 A/B，但不强制每次出三份稿。
- 组合到正式章节生成时，向主 Skill 返回经验证的可用语言稿，或返回 Protect / No Change；最终 Manuscript 写入权限仍归调用方和项目工作流。
- 没有真实独立盲评时不称“盲评通过”；没有完整合法外部范文时不称“已逐字对读”。参考其他作家的作品只提炼可迁移语言工艺，不复刻具体句子和标志性表达。

## 停止条件

发现高影响 Canon/角色/剧情缺口时停止编辑并定位真正 Owner；发现当前已有文字成立且改动只会磨平它时，明确保护原稿。只要用户指定纯文笔，始终守住这一范围，不发散故事方案。
