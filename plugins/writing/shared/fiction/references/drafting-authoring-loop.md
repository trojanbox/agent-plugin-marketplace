# 正式正文成文的近端执行方法

仅在 fiction-manuscript-drafting 已通过 Readiness Gate，且用户要求正式章节成文/续写/重写时读取。只做 Ready/Not Ready 检查不加载此文件。


### Skill Composition｜成稿后自动语言精修

- **默认触发（必须执行）**：每次新写、续写或实质重写出一章**准备交付的正式小说 Manuscript**，先完成初稿及 Reader Pass，随后加载 writing/fiction-prose-editing 做一次“诊断 → 必要时局部编辑 → A/B / Protect”检查；对出版向与网文向都有效。没有可靠收益时返回 Protect / No Change，不强制修改。
- **不触发**：用户只要未经精修的草稿、章节尚未写完，或任务只是章纲、Readiness、无文笔目标的小型勘误。
- 已有小说只要纯文笔精修 → prose-editing 为主；只诊断文风漂移 → fiction-review 的表达模式为主。Drafting 保留正式成文及写入职责。


### 1. 建立近端 Writing Frame

权威恢复后，把当前写作范围收缩成最小集合：

- **Chapter Engine**：人物现在实际在做什么；
- **Hard Anchors**：若遗漏会破坏 Story 因果 / 关系 / reveal 的少量节点；
- 人物此刻目标、身体 / 压力 / 现实限制；
- 当前关系阶段与互动权限；
- 当前信息开放 / 禁止边界；
- 上一章必须承接的状态；
- 当前作品 Style 的硬边界；
- 已确认 Voice Baseline 中与本章最相关的少量实现特征；
- **Creative Open**：对白、小动作、环境、生活摩擦、低影响场景顺序等允许现场生成的空间。

项目已有 Rolling Plan 时从中读取这些内容；没有时在本轮内部临时收缩，不强制写入 `outline/`，也不把完整合同逐条变成生成清单。

### 1.1 创作激活与审查依据分层

完成项目要求的 Author Preference / Mistakes Preflight 后，再整理成文时的最小激活窗口，**不减少必需读取，也不降低事实校验**：

- **始终生效的硬边界**：World / Story / Character Canon、POV、人物当前知道与不能知道的事、关系权限、重要因果、信息释放、连续性，以及命中 Active Mistake 中涉及这些事实的防回归约束。
- **供写作参考的软偏好**：当前场景真正相关的少量 Voice 机制和作者审美。其它已读取的偏好与检查项留到成稿审查，不逐句当成必须展示的写作任务。
- **当前场景发动机**：人物现在想做什么、什么正在阻碍他、读者此刻主要牵挂什么；允许自然的失败、生活时间与不直接产出剧情节点的行为。

不要按每个 Hard Anchor、Preference 或 Mistake 各写一段示范场景。这里的“最小”指生成时的注意力分配，**不能以自由创作为由越过已确认硬约束**。


### 2. 有既有正文时先做 Voice Calibration

当任务属于续章、新会话恢复、整章重写，或用户要求增强某个表达维度时，读取 `manuscript-drafting.md` 的 Voice Calibration / Feedback Delta 部分。

核心要求：

- 抽象 Style 负责边界，已确认正式正文负责实现级校准；
- 只提取观察方式、场景呼吸、对白摩擦、人物欲望、幽默 / 情绪机制等可复用特征；
- 不复制原句、固定句式、口头禅或表面节奏；
- 用户说“更幽默 / 更紧张 / 更伤感 / 对白多一点”时，在既有 Work Voice 内做增量调整，除非用户明确要求重设 Style。

### 3. 从正在发生的事情成文

- 先让人物继续做眼前的事，再让对白、心理、环境和信息从行动里长出来；
- **不要把 Hard Anchors 拆成一个锚点对应一个场景的施工清单**；同一段连续行动可以自然承载多个背景事实；
- 允许人物漏接、说多、失败、找补、沉默或换话题，只要符合当前关系和现实条件；
- 不为了满足 Character / Style / Story 标签专门制造示范句或说明段；
- 技术 / 世界信息写到足以支撑当前行动和读者理解即可；
- Creative Open 可以现场发现，只要不改变高影响 Canon、关系权限和信息释放。

### 4. 每完成 1～3 章，允许计划反向更新

持续创作模式下，正式 Manuscript 是下一批章节的重要事实输入。写完一小批后：

- 连续读当前新章与上一章；
- 记录人物实际形成的关系 / 行动余波；
- 若项目维护 Rolling Plan，只更新接下来 1～3 章；
- 旧计划与实际正文冲突时，先判断是否影响 Canon：普通实现以正式 Manuscript 为准，高影响冲突回真正 Owner 处理。

### 5. 先连读初稿，再执行完整 Postflight

完成一个连续场景或完整章节后，先暂时放下写作清单，用第一次阅读的读者视角连读：

- 读者当前愿意跟着哪个人、等待什么结果？阅读注意力是否被无关技术步骤或作者总结夺走？
- 哪些对白、动作、等待和普通生活细节已经让人物成立？先标为 **Protect / Preserve**，不要在修订中顺手抹平。
- 是否存在真正让读者卡住、失去期待或不相信人物的地方？只记录有原文证据的问题；普通安静场景不强制制造反转、冲突或章尾钩子。

随后按上面的触发条件执行 prose pass，再重新激活完整项目合同与审查清单。读取 `manuscript-drafting.md` 的 Postflight 部分，至少检查：

- Character：人物目标、默认社交姿态、压力路径有没有漂；
- Continuity：身体、物件、位置、关系余波、已知信息有没有跳变；
- Information：有没有作者知情泄漏或提前消费后续真相；
- Voice：和当前 Voice Baseline 对读后，是否仍像同一本书；
- Feedback Delta：本轮局部反馈“加强某维度”的要求有没有覆盖整体 Work Voice；
- Overexecution：正文有没有变成章纲逐项展开、合同说明文、喜剧小品或其它单一技巧展示。

发现命中时继续修订，不能把已知回归直接交给用户。
