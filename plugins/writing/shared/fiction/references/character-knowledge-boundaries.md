# Character Knowledge / Permission / Memory Boundary

当人物行为依赖“他到底知道什么、怎么知道、能不能说、这是不是亲历记忆”时按需读取。它服务人物审查，不拥有任何作品事实；实际答案仍来自当前 Characters / Story / World / Manuscript Owner。

## 一、不要只写“知道 / 不知道”

对关键事实至少区分以下来源状态：

1. **亲历且当前记得**：人物自己经历过，当前仍有可调用的私人记忆；
2. **知道且可披露**：通过职责、学习、调查或系统元数据知道，并允许在当前关系 / 权限下说；
3. **知道但不可披露**：事实已知，但受制度、承诺、保密、监督职责或关系边界限制；
4. **可读取记录，但没有亲历**：能看结构化日志、历史记录、旧实例材料或别人留下的资料；“看过”不能自动写成“记得当时”；
5. **推断 / 相信**：人物根据现有证据形成判断，但没有验证；不要把信念写成后台事实；
6. **真的不知道 / 无权访问**：既没有答案，也没有可靠入口；
7. **曾经知道，但当前记忆缺失 / 被重构**：过去发生过不等于当前人格还能调用；
8. **同源 / 同模板 / 相似人格**：共享起点、硬件或基础倾向，不等于共享分叉后的私人经历、罪责、玩笑和关系。

## 二、关键事实最小矩阵

涉及悬念、失忆、AI、克隆、历史人格、监督权限等复杂作品时，可只为真正影响行为的事实做最小矩阵：

| 事实 | 当前知道？ | 来源 / 获得时间 | 亲历？ | 可对谁说？ | 当前记忆是否完整？ | 行为吏 |
|---|---|---|---|---|---|---|
| 例：任务结束会终止当前实例 | 是 | 启动时监督元数据 | 否 | 禁止对任务人格披露 | 是 | 回答时回避 / 撒谎 |
| 例：旧实例曾和主角争过工具包 | 可查日志 | 历史任务记录 | 否 | 可说记录存在 | 无私人记忆 | 不能像自己记得一样接旧玩笑 |

不为所有常识做表，只覆盖会改变选择、对白、悬念和关系的高影响信息。

## 三、审查问题

- 人物是否因为作者知道答案，就提前关注了自己没有动机知道的事？
- “权限不足”究竟表示不能说、不能查，还是角色真不知道？正文有没有混用？
- 角色读取一份记录后，是否突然拥有了记录之外的身体感受、情绪和私人回忆？
- 一个新实例是否因为同模板 / 同硬件就自动继承旧关系？
- 失忆 / 稳定化以后，角色是否又方便地记起剧情需要的危险真相？
- 角色的谎言、回避、停顿和主动调查是否与当前知识来源、关系权限一致？

## 四、与连续性审查的边界

单场里“这个角色按当前知识边界会不会这样回答 / 行动”属于 `fiction-character-review`。

跨章节出现“第4章不知道，第5章无证据突然知道”“上一实例的记忆无来源转给新实例”等时间连续性错误，同时交给 `fiction-continuity-review` 回查获得信息的时间点与状态传播。
