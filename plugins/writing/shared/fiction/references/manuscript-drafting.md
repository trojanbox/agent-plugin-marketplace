# Manuscript Drafting：Voice Calibration、Feedback Delta 与 Postflight

本 reference 供 `fiction-manuscript-drafting` 在**已有正式正文、跨章续写、新会话恢复、实质重写或用户要求加强某个表达维度**时读取。

它只提供恢复和检查方法，不提供通用小说文风。作品实际声音仍由当前 Book Style、Characters、Story、Knowledge、已确认 Manuscript，以及存在时的近期 Planning 决定。

## 0. 创作窗口与审查窗口

本文件的原则须配合当前项目 Preflight 使用：**先完整读取必须加载的 Author Preference、Active Mistake 与 Canon，再收缩生成时的注意力；交付前重新使用完整约束检查。**

- 创作时一直保持硬边界：作品事实、人物知识与关系权限、POV、信息释放和真实防回归风险。
- 软审美规则只激活本场最相关的少量观察方式、人物欲望与表达机制。不要把每张卡片转成一句台词、一个动作或一个场景。
- 当前场景先看人物的切身目的、现实阻力与读者对这段经历的兴趣。读者兴趣可以来自相处、等待、微小变化，不要求每场升级危险或每章强留悬念。
- 不需要另建生成清单、评分表或多代理步骤；完整审查仍在成稿以后进行。

## 1. Voice Calibration

### 1.1 来源优先级

项目已经声明 Voice Baseline 时，按项目自己的权威顺序读取。没有项目特定顺序时，可使用：

1. 当前有效、用户已确认的正式 Manuscript；
2. 上一章与当前章相邻的正式正文；
3. 当前 Work Voice Contract / Anti-Voice；
4. Character Voice、Story 信息策略，以及存在时仍有效的近期 Planning；
5. 历史旧稿只作为低优先级表达证据，前提是项目明确允许且不与当前 Canon 冲突。

聊天里刚生成但未确认的候选稿、用户已经否决的版本、未落入正式 Manuscript 的草稿都不构成 Voice Baseline。

### 1.2 校准提取什么

从样本中提取少量**实现机制**，例如：

- 叙述通常先看身体、物件、空间还是抽象判断；
- 场景怎样真正移动，叙述和对白怎样分工；
- 人物说多 / 说少的差异怎样出现；
- 对话允许多少漏接、废话、失败和自然转弯；
- 幽默来自人物欲望、处境、关系错位、制度荒唐还是其它机制；
- 情绪怎样从具体行动或身体变化进入；
- 一个笑点、冲突或漂亮句通常在什么位置停止，不继续榨取；
- 技术 / 世界信息写到什么粒度就继续行动。

不要提取成固定字数、固定段长、固定笑点数、万能句式或角色口头禅。

### 1.3 新会话恢复

新会话最容易只恢复“人物卡和 Style 规则”，却丢失实际写出来的呼吸。项目已有正式章节时：

- 优先完整读取上一章；上下文不足时至少保留章尾 + 项目指定的代表性 Voice 样本；
- 先判断上一章哪些实现已经被用户认可，再开始当前章；
- 起稿前用一句内部问题校准：**如果遮掉人名和专有名词，这段场景运动和人物摩擦还像上一章吗？**

## 2. Feedback Delta / 局部反馈守恒

用户常会说：

- “这一章幽默感高一点”；
- “紧张一点”；
- “别这么平”；
- “对白再多一点”；
- “更有人味”；
- “这里爆发得更狠”。

默认解释为：**在当前 Work Voice 内调整一个维度的强度或出现机会**。

执行时先冻结 Preserve Set：

- POV / Narrative Lens；
- 角色当前关系权限和声音差异；
- 已经确认的叙述与对白分工；
- 信息释放顺序；
- 作品 Anti-Voice；
- 当前章节职责和连续性。

然后只调整用户点名的维度。

### 2.1 过度补偿信号

出现以下任一信号时，优先判定局部反馈覆盖了作品基线：

- “更幽默”后几乎每轮对白都出现包袱；
- “更紧张”后所有人都提高音量、动作加速、没有普通时间；
- “更伤感”后旁白开始持续解释情绪和意义；
- “对白更多”后叙述、空间、身体和动作被挤掉；
- “更有人味”后为了口语感刻意堆废话、错字或网络表达；
- 用户只改一个局部维度，新稿却像换了一本书。

### 2.2 幽默增强的通用检查方法

当用户要求提高幽默感：

- 优先增加不同真实处境中的幽默机会；
- 每个笑点仍由人物当前欲望、失败、虚荣、误解、制度摩擦或关系错位驱动；
- 笑点已经成立后允许场景继续，不要求升级到标准 punchline；
- 不把另一个角色长期固定成递梗 / 捧哏工具；
- 允许笑话没人接、找补失败、人物自己换话题。

具体“什么好笑”继续服从当前作品 Style 与 Character Voice。

## 3. Postflight

交付完整章节前，先完整连读这一章，再把完整合同重新拿回来检查。

### 3.0 读者体验与保留集

先暂时不按合同逐条打钩，回答：

- 当前读者真正想追随的对象是什么？整段是否一直迫使读者听一个无关的技术说明或主题总结？
- 是否有足够的场景运动与人物自己的行动、误解、等待和选择？不要求每一场都出现高潮。
- 哪些具体对白、动作、物件或安静时间本来就有效？先形成小范围 Protect Set。
- 哪些真实问题值得修改？指出原文及读者会在哪儿失去兴趣或被迫“解题”。不要把另一种表达偏好伪装成缺陷。

只有找到明确问题才进入定向修订；避免用更短、更工整代替更好，也不要为省去流程把人物生活时间一起删掉。实质重写涉及可比旧稿时再进入 A/B 修订验收。


### 3.1 Canon / Continuity

- 当前章有没有静默改变 World / Story / Character 事实；
- 上一章的身体、位置、物件、关系、情绪余波是否连续；
- 后一章的关键事件、关系和信息有没有被提前消费；
- 角色有没有使用当前不该知道的信息。

### 3.2 Character

- 人物此刻的行动是否来自当前目标和压力；
- 默认社交姿态、关系阶段与互动权限有没有跳级；
- 性格标签是否被写成示范句；
- 人物是否共享同一种聪明、幽默、尖锐或正确表达。

### 3.3 Work Voice

把新稿和项目指定 Voice Baseline 对读：

- 场景运动、叙述镜头和信息进入方式是否同源；
- 对白有没有突然变得更整齐、更高命中；
- 叙述有没有被某个局部技巧挤掉；
- 已经成立的生活感、温度、粗糙度或失败空间有没有消失；
- Anti-Voice 中明确禁止的退化方向有没有回来。

### 3.4 用户本轮要求

- 用户点名的问题是否真实改善；
- Preserve Set 是否仍成立；
- 调整是否只发生在目标范围，没有把整章全部改成一种强度；
- 用户明确喜欢的上一版特征有没有被一起磨掉。

### 3.5 最终问题

> 这一章现在像人物在真实现场继续生活和行动，还是像作者在展示刚刚收到的写作指令？

如果更接近后者，继续修订。
