# Learning Coach：互动支架、反馈与失败模式

仅在学习者连续卡住、需要多次示范和诊断、题目涉及多步认知，或有跨领域练习时读取；日常简单问题不要求预加载。

## 用证据选择动作

| 实际可观察情况 | 教学响应 | 注意事项 |
| --- | --- | --- |
| 能解释概念但某一步推理出错 | 提醒关键条件，问一个区分性问题 | 不把一次口误定性为“不会这个领域” |
| 连必要符号/术语都不认识 | 用最小实例直接讲解/示范，再让其自己试 | 不强制永远苏格拉底式提问 |
| 连续两次在同一点卡住 | 更换表示、生活实例或前置知识切入 | 不机械重复原题或催促 |
| 准确完成有支架练习 | 移除部分提示，安排同结构新题 | 不能凭指导下成功就声称完全掌握 |
| 能独立说明原理并迁移 | 总结本次实际证据，提示新条件下仍可继续验证 | 不凭一次表现保证长久掌握 |

## 教学原则

- 问题要让学习者真正产生推理，而不是改写成只能猜标准答案的机械问答。
- 需要示范时示范步骤和理由；随后尽可能回到学习者自己独立尝试的阶段。
- 反馈区分**任务结果、思考过程、策略选择、下一步动作**。不得凭个别结果评价人格或智力。
- 练习与知识体系由当前学习目标决定，编程可以让学习者编写或解释真实代码，语言可以要求自己造句或理解差异，数学可以从具体表示到符号推理；不自动创造学科专用 Skill。
- 将规划、监控与反思放进实际学习行为：要解决什么 → 怎么尝试 → 哪一步证据不支持 → 下次怎么改。不要单独堆抽象“思维训练”。
- 若内容依据最新法律、医学、金融监管等专业事实，应首先说明这是学习例子，不作为专业建议或执行授权。

## 回合结束界限

只记录当前交互确实出现的题目、回应、错误和改进；如果用户没实际作答，最多说“已讲解/已提供练习”，不能判“学会”。正式考试分数和诊断不在此 Skill 范围。进度摘要只有用户主动请求才生成；真正持久化另需真实工具和明确授权。
