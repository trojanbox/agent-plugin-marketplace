# 审核、迭代和导出

需要展示或修改卡片、分批审核、导出和后续修订时加载。

## 审核流程

1. 为所有候选笔记分配稳定的 C001、C002… 编号；修改不改号、删除不重排，新卡分配从未使用的编号。
2. 按主题或章节分批完整展示卡片，不用前五张代表全体；每张至少显示卡型、正面、背面、来源，存在补充说明/事实核查状态时同时显示。
3. 用户可以说“删除 C005、修改 C007 答案、增加一张关于……”；只变更明确点及受其影响的关联内容，并复核重复、事实、类型和编号稳定性。展示修改后的卡片和总数。
4. 所有批次审核完成后列出整体数量、卡型及仍存疑条目；只有用户明确说“确认生成/可以导出”等才开始写 `.apkg`。沉默或只说“继续下一批”不算确认。
5. 单个卡或整批无法安全核查时，暂不纳入最终文件；告诉用户哪些内容被排除及为什么。JSON 不承载用户已否决的卡片。

## 打包依赖的隔离安装

正常使用已有的 Python 虚拟环境安装 `scripts/requirements.txt`。如果宿主系统禁止全局 pip 安装、又缺少 `python3-venv`，可选择用户可写的隔离目录，例如 `python3 -m pip install --target /tmp/anki-deck-deps -r scripts/requirements.txt`，并在执行 Python 脚本时设置 `PYTHONPATH=/tmp/anki-deck-deps`。不要使用 `--break-system-packages` 或擅自修改宿主 Python 环境。不同系统按实际临时目录及环境变量语法调整。

## 生成和再次更新

- `cards.json` 是用户可保留的版本化事实输入；首次生成后，与 APKG 一起交付。**仅保留 APKG 而没有原 JSON，无法保证后续按原 GUID 更新。**
- `deck_id` 和已存在卡片 `id` 不得因标题/答案修改而变化；同一 id 的卡型也不能静默切换。新增笔记分配新 id。
- 修改后的 JSON 用 `--previous old.json` 对比，可发现卡型更换、身份误复用及原牌组 ID 变化。
- **从新版 JSON 删除某张旧笔记，不代表导入新 APKG 会删除 Anki 已存在的旧笔记**；提示用户必要时在 Anki 中人工处理。
- 因 Anki 数据库已有状态不同，稳定 GUID 不保证所有导入都能如期更新或保留复习记录。不要写“已同步”。
- 标明确定性构建器不执行事实核查、用户审核或访问历史会话；它只根据最终确认的数据生成文件、校验包结构。
