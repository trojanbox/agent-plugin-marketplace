# Deep Research 来源层级、Claim-Evidence、冲突与 Exit Gate

进入深挖阶段后读取，用于来源验证、主张证据绑定、冲突处理、覆盖检查和停止条件。

### Phase 5 — Source Validation

#### 默认来源层级

一般情况下优先：

1. 原始资料：官方文档、法规、论文原文、原始数据、公司公告、项目仓库；
2. 高质量二手资料：专业媒体、行业研究、系统综述、权威机构分析；
3. 专业人士公开分析：具备明确身份、方法和证据的专家文章 / 访谈；
4. 社区与用户反馈：论坛、Reddit、HN、GitHub Issues、评论、社交平台；
5. 聚合、SEO 或来源不透明的转述内容。

这不是固定信誉排名。**研究问题决定什么是一手证据。** 例如研究某工具的开发者社区体验时，GitHub Issues、HN 或 Reddit 的原始讨论具有直接证据价值。

#### 最低验证项

对承担关键结论的来源检查：

- 是否真正在回答当前问题；
- 发布时间 / 数据时间是否合适；
- 是否为原始来源还是转述；
- 作者 / 机构是否可识别；
- 数字的样本、口径、单位、地区是否匹配；
- 多个来源是否其实来自同一个上游数据，不把转载数量当独立验证。

### Phase 6 — Claim ↔ Evidence

研究过程中维护轻量的证据映射。无需把内部工作表原样展示给用户，但重要结论必须能够回答：

> “这句话具体由什么证据支持？”

推荐结构：

| Claim | Evidence | Source | Strength / Caveat |
|---|---|---|---|
| 核心结论 | 数据 / 原文 / 案例 | 原始来源 | strong / 限定条件 |
| 社区倾向 | 多个独立讨论中的高频模式 | 社区样本 | 样本偏差 |
| 推断 | 多项已验证事实的综合 | 对应来源集合 | inference |

明确区分：

- **Verified fact**：来源直接支持；
- **Reported claim**：某来源这样声称，但尚未独立验证；
- **Inference**：基于多项证据的推断；
- **Unknown / unresolved**：现有证据不足。

### Phase 7 — Evidence Conflict Resolution

遇到可信来源冲突时，依次检查：

1. 定义是否一致；
2. 时间范围是否一致；
3. 地区 / 样本 / 用户群是否一致；
4. 指标和统计口径是否一致；
5. 一手数据与转述是否混用；
6. 是否有更新版本或更直接来源；
7. 来源之间是否真正独立。

只有证据足够时才解释哪个结论更可信。仍无法消解时，在最终答案里保留冲突并说明原因和影响。

### Phase 8 — Coverage & Gap Check

在准备收口前检查：

- 用户问题的每个关键部分是否都有证据；
- 是否只看到了支持某一结论的材料；
- 是否遗漏会改变判断的重大反例或限制；
- 核心数字是否有原始来源或可靠交叉验证；
- 当前/最新类信息是否足够新；
- 社区观点是否把个别高赞帖子误当成整体共识；
- 是否还有一个明显的信息缺口会实质改变最终建议。

缺口存在但不会改变主要结论时，可以停止并在答案中注明限制。

### Phase 9 — Exit Gate

满足以下条件即可结束研究：

- 关键研究维度已有足够证据；
- 核心结论能够追溯到来源；
- 重大冲突已经调查，或明确标记为未解决；
- 新一轮检索没有产生会改变核心判断的高价值信息；
- 剩余缺口不影响用户当前决策，或已被明确披露；
- 用户要求的范围已经覆盖。

如果任一**关键**条件不满足，继续定向调查缺口；不要重复做已经没有新增信息的广泛搜索。
