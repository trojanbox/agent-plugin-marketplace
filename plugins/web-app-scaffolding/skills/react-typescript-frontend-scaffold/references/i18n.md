# i18n

在新增用户可见文案、Locale、日期/数字/金额格式、翻译资源或语言切换时读取。

## 1. 默认技术与 Package

```text
packages/i18n
→ i18next + react-i18next
```

默认语言 `zh-CN`，同时内置 `en-US`。

不默认引入：

```text
i18next-browser-languagedetector
i18next-http-backend
FormatJS / React Intl
Translation Compiler
远程翻译服务
```

真实需求出现后再加。

## 2. Package 结构

```text
packages/i18n/src/
├── locales/
│   ├── zh-CN/
│   │   ├── common.json
│   │   ├── auth.json
│   │   └── websites.json
│   └── en-US/
│       ├── common.json
│       ├── auth.json
│       └── websites.json
├── i18n.ts
├── locale.types.ts
├── locale.constants.ts
├── locale.utils.ts
└── index.ts
```

它是 Workspace Source Package，不独立 bundle/dist；消费端 Vite 编译。

## 3. Locale Contract

```ts
export const SUPPORTED_LOCALES = ['zh-CN', 'en-US'] as const
export type Locale = (typeof SUPPORTED_LOCALES)[number]
export const DEFAULT_LOCALE: Locale = 'zh-CN'
```

解析顺序：

```text
用户保存语言
→ navigator.languages
→ zh-CN fallback
```

用薄封装实现，不默认装 Detector 插件。

## 4. Namespace 跟业务领域走

推荐：

```text
common
websites
auth
publishing
settings
```

Feature：

```tsx
const { t } = useTranslation('websites')
return <h1>{t('list.title')}</h1>
```

不推荐：

```tsx
t('websites.list.title')
```

namespace 已表达领域，不重复。

## 5. Translation Key 使用稳定语义

推荐：

```json
{
  "list": {
    "title": "网站管理",
    "empty": "暂无网站"
  },
  "actions": {
    "create": "创建网站",
    "delete": "删除网站"
  }
}
```

不推荐中文正文作 key：

```tsx
t('创建网站')
```

也不写超长机械 key：`websiteManagementPageWebsiteListMainTitle`。

原则：**namespace 表达领域，key 表达局部语义。**

## 6. 用户可见自然语言必须走 i18n

```tsx
const { t } = useTranslation('websites')
<Button>{t('actions.create')}</Button>
```

不要：

```tsx
<Button>创建网站</Button>
```

包括标题、按钮、提示、错误、空状态、Label、Helper Text、状态描述和 Locale-sensitive display。

不需要翻译：Route/API Path、CSS class、日志 key、错误 code、技术 identifier、测试内部标识。

## 7. `packages/ui` 不依赖 i18n

```text
packages/ui   → 文案无关的 UI Primitive
packages/i18n → i18n 基础设施
Feature       → 同时消费两者
```

Button/Dialog 不在内部 `useTranslation()`；由调用方传 children/title/content。

Radix Primitive 同样保持文案无关。

## 8. 日期 / 数字 / 金额

统一用 Web Platform：

```text
Intl.DateTimeFormat
Intl.NumberFormat
Intl.RelativeTimeFormat
Intl.ListFormat
```

可在 `packages/i18n` 封装：

```text
formatDate
formatDateTime
formatNumber
formatCurrency
formatRelativeTime
```

不因为基础展示默认引入 moment/dayjs/date-fns。复杂日期计算/时区需求真实出现后再选型。

## 9. Translation Resource

第一版静态随 Bundle：

```ts
import zhCNCommon from './locales/zh-CN/common.json'
```

不默认远程下载、HTTP backend、自动 namespace lazy loader。资源真正膨胀或独立发布时再升级。

## 10. Missing Translation

开发环境缺 key 必须暴露：console warning/error，并尽量显示可定位 key，例如：

```text
websites:actions.create
```

禁止静默空字符串。

## 11. Review Gate

- 用户可见自然语言是否硬编码？
- namespace 是否按领域组织？
- key 是否稳定且没有重复 namespace？
- 是否出现巨大单一 translation.json？
- packages/ui 是否错误依赖 i18n？
- 日期/金额/数字是否 Locale-aware？
- 是否无真实需求引入 Detector/HTTP Backend/Compiler？
- Missing Translation 是否能在开发阶段发现？
