# Forecasting Mode / 预测与情景推演

当用户要求“未来会怎样、什么时候可能发生、风险何时显化、有哪些情景、什么信号意味着概率上升/下降”时读取。它扩展科学推理闭环，不替代领域 Skill。

## 一、先定义预测合同

先明确：

- **As-of**：判断基于什么时间点的信息；
- **Horizon**：预测讨论的是几周、几个月、几年还是更长；
- **Target**：到底在预测事件、方向、阶段转换、风险暴露还是结果区间；
- **Reference class / Base rate**：有可比历史或基准时先看基准发生率；
- **Known constraints**：法律生效日、产品发布日期、合同到期日、物理周期等已知硬时点与推测性时间分开。

用户没有给精确时间范围、但已有足够上下文时，选择与问题自然匹配的 horizon 并明确写出，不为了填模板反问。

## 二、情景结构

默认先建立 **Base case**，只有存在实质替代路径时再增加上行/下行或其它情景，不机械凑三个。

每个重要情景至少说明：

1. 当前哪些事实支持它；
2. 通过什么机制演化到该结果；
3. 哪些前置条件必须成立；
4. 哪些 Leading Indicators 会先变化；
5. 哪些 Trigger / Threshold 出现后应明显提高该情景权重；
6. 哪些反证或反向指标出现后应降低权重；
7. 当前相对置信度与主要未知。

场景之间要能被未来观察区分，不能只是把同一个判断换成“乐观 / 中性 / 悲观”措辞。

## 三、时间判断

时间预测优先输出**条件化窗口**：

```text
若 A / B 条件在未来 6～12 个月内出现，风险更可能进入显化阶段；
若关键指标 C 持续改善，则该窗口应后移或当前情景降权。
```

只有存在可靠的外部日程、物理/制度约束、重复周期或经过验证的时间模型时，才给精确日期。

禁止因为用户问“哪一年 / 什么时候”就硬给一个单点年份。没有可靠依据时，给阶段、区间、条件和领先指标，并明确精度边界。

## 四、概率与置信度

- 有校准数据、明确模型或可审计频率基准时，可以给概率或区间，并说明来源；
- 没有这些条件时使用 `Leading / Plausible / Weak` 或 `High / Medium / Low` 等相对置信度；
- 不用 `73%` 一类伪精确数字表达主观感觉；
- 新证据出现后，说明**哪个情景被加权、哪个被降权、为什么**。

## 五、Leading Indicators 优先于故事

预测交付物至少要让用户知道“接下来观察什么”。优先选择：

- 能先于结果变化的指标；
- 与机制链直接相关的指标；
- 能区分两个主要情景的指标；
- 用户能持续获取或验证的指标。

不要罗列几十个指标。优先给少量真正会改变判断的信号。

## 六、推荐输出

复杂预测可使用：

```markdown
## As-of 与时间范围
## 当前基准事实 / Base Rate
## Base Case
- 机制
- 必要条件
- 时间窗口
- Leading Indicators
- 反证 / 降权条件

## Alternative Scenario(s)
...

## 当前情景排序与置信度
## 接下来最值得观察的信号
## 什么证据会改变预测
```

简单问题不强制套完整模板。

## 七、领域边界

- 预测某个宏观市场、股票或投资组合的主要目标 → `finance` 主导；本模式只提供科学推理框架；
- 需要补充最新外部证据 → `research/deep-research` 作为辅助；
- 需要用历史数据校准概率或检验预测 → `data/statistical-analysis` 作为辅助；
- 本模式不把“讲得完整”当作预测准确性的证据。
