# Claim Ledger 与辩论留档

每个子命题保留独立记录，不因其它子命题胜负改变它的状态。

```text
C-001
Original: AI 无法替代业务层和架构层。
Versions:
  v1 / R0: 原命题。
  v2 / R1: 功能必要性与执行者身份分开（用户接受后生效）。
Attack:
  R1 / Logic: AI 本身也可能承担需求分析和系统设计；功能必要不推出人类职业不可替代。
  撤回条件: 给出在明确范围内只能由人类承担该功能的必要条件及证据。
Response / Evidence: 记录用户实际回应和来源，不代写回应。
Status: narrowed（仅在回应支持收缩且用户接受后）。
Current: 复杂软件生产不能跳过问题定义和系统设计，但这些功能未必永久由人类承担。
Open: 哪些场景仍需要人类判断，依据是什么？
```

本示例不是 AI 当前能力的实证结论。若用户尚未回应，状态保持 unresolved，v2 仅为候选。

每轮默认只展示目标命题、Steelman、攻击类型与证据、撤回条件，以及一个聚焦回应点。回应后输出本轮账本变化，长历史可折叠为文件，原文与版本不得丢失。

GitHub 正文保存：`Original Claim`、范围、子命题与初始账本；每轮评论保存攻击、实际回应、证据日期、撤回情况和版本变化；最终正文可增加当前结论摘要，但不能覆盖历史命题。Issue 标题始终以 `【辩论】` 开头。同轮已存在 Issue 时更新原记录，新轮明确关联历史轮次；仓库与写权限不明确时先完成可交付内容，并说明待补信息。
