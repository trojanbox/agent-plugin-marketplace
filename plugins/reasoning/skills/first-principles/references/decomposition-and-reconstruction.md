# 第一性原理：约束审计与方案重建

触发：任务包含复杂的架构或流程重构、多个约束相互牵制、成本拆解与数量级对比，或者用户要求留下可审计的假设账本。普通一次性问答只需主 SKILL.md。

## 一、建立假设与约束账本

每条都保留：

- **Claim**：具体、可反驳的命题，禁止“成本很高”“大家都不喜欢”等模糊表述。
- **Layer**：已观测事实 / 逻辑数学限制 / 自然物理限制 / 法律制度 / 资源与能力限制 / 可改变的组织规则 / 行业惯例 / 个人偏好。
- **Evidence**：出处、估算依据、适用人群/时间；未知时写“待核验”，不编造证据。
- **Binding**：在当前目标/情境下是否硬约束；法律具有辖区与生效时间，预算通常由情境决定；偏好不能伪装成物理事实。
- **Alternative**：如果撤掉这条假设，会释放什么设计空间，会引入什么新代价。
- **Test**：什么观察、计算或小实验会改变这一判断。

注意三种常见误判：把当前技术局限当成永恒物理极限；把行业惯例当成普遍必需；把主观价值选择说成由物理学自动推导出来。基础事实越少越清楚，但删掉关键约束会产生虚假的自由度。

## 二、目标拆解：用需求表述结果

用“谁，在何种条件下，需要完成什么，成功怎么判断”重述目标。区别：

- **目的**：需要可靠的通勤可达性。
- **现有手段**：每天开自有汽车。
- **潜在硬约束**：到达时间窗口、特殊乘客需求、可支付费用、当地交通条件。
- **需验证的假设**：拥有汽车必然比公共交通、打车或组合方案更可靠。

仅在需要时考虑购车、租车、公共交通等不同手段。不能用“最低成本”取代用户明确更看重的安全、独立性或时间价值。

## 三、从最小可行条件向上构建

1. 列出结果成立的必要条件，区分必要、充分与促进条件；避免把一个可行解当成唯一解。
2. 画最短依赖链：底层约束 → 必要能力 → 可替换实现手段 → 预期结果。
3. 找出最敏感的变量、真正的瓶颈和可交易条件；通过数量级核算排除明显不可能的方案。
4. 产生结构上不同的路线；逐条说明它用什么新假设换掉了旧假设。
5. 将安全、可靠性、可维护性、转换成本、外部性、人类激励与制度要求回填。
6. 比较原方案和新方案在相同指标与情景下的表现，允许“保留原方案”成为最合理的结论。

## 四、反向检查

- 如果关键数量级估计偏差 2～10 倍，方案是否仍然成立？
- 方案的每一步是由已确认条件推出，还是暗中加入了新的假设？
- 是否把“物理允许”误读成“工程可实现、商业可行或社会可接受”？
- 哪个没有纳入的参与者有权拒绝、拖延或改变结果？
- 如果试验失败，哪些基本假设需要回滚？是否有更小、可逆的试验？

## 五、可复用的交付骨架

- **真正需求与成功指标**
- **不可绕过的约束**：证据充分 / 当前条件限制 / 未验证
- **历史惯例与待质疑假设**
- **最低必要依赖链**
- **新旧方案对照**：成本、时间、风险、受益人、失败条件
- **优先验证的关键前提**
- **暂定判断**：当前可做、条件成立才可做、证据不足需停下

输出必须标明“已验证”和“待验证”；没有真实实验或现有数据时，不声称定量收益或真实效果已经达成。
