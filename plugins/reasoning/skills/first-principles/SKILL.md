# First Principles / 第一性原理

## 唯一目标

帮助用户跳出沿袭的方案，在**目标清楚、基本事实与不可绕过的约束有据可查**的前提下，从底层重新构造可行方案，说明它为什么成立、什么条件下不成立以及如何验证。目标是可检验的重构，不追求为了反常识而反常识。

## 什么时候使用

高信号：从第一性原理思考；假设从零开始设计；为什么一定要沿用这个流程；去掉行业惯例还剩哪些必要条件；能否从物理、成本或人的实际需求重新推导方案；有没有被默认当作事实的假设。

- 主要是解释“现象为什么发生”、比较竞争性因果假设、验证猜想 → reasoning/scientific-reasoning。
- 主要是解释行为者互相影响、反馈回路、反身性与长期演化 → reasoning/systems-thinking。
- 仅需要大量新奇想象的开放式创意种子 → reasoning/divergent-ideation；明确观点逐轮攻防 → reasoning/structured-debate。
- 具体代码架构、生产修复与研发决策 → development；K-12 教学方案 → education；投资建议、财务分析 → finance。当前 Skill 可提供重构视角，不接管这些领域的正式交付与权限。

## 核心闭环

1. **目标与评价标准**：写清真正要满足的需求、目标人群、可衡量的成功条件，以及用户明确给出的禁区。不把当前流程、产品形态或常用指标预设为目标。
2. **现有方案与隐含假设**：把“我们一直这样做”“行业都这样”“技术上做不到”等拆为可独立核查的具体命题；指出每条现有规则在解决什么问题。
3. **基础事实与约束分层**：区分可观察事实、数学/物理/逻辑限制、现行法律及制度性限制、资源与时间边界、可改变的组织规则、行业惯例和个人偏好。每条注明依据、适用情境与未验证部分；不要给未经证明的说法贴上“第一性原理”标签。
4. **剥离与重建**：暂时移开可质疑的惯例，保留已经确认的约束；从最小必要条件向上推导至少一种结构不同的方案。有多种实质不同的路线时再对比，避免为了凑数换名词。
5. **现实回填与推导检查**：恢复预算、成本、能力、法律、安全、维护、迁移与人类行为等真实约束，检查新方案有无隐藏假设、瓶颈、机会成本或不可实施环节；必要时做量纲/数量级检查。
6. **验证与修正**：针对最容易使方案失效的前提，设计低成本实验、原型、查证或明确的停止条件。新证据不支持时，退回修正推导，保留既有方案可能更优的结论。

## 默认交付

按复杂度控制篇幅，优先交付：**真实目标 → 基础事实/约束（含依据或未知）→ 被打破的惯例 → 重新推导的方案 → 取舍与风险 → 最小验证步骤**。若基本事实缺失，只能交付有条件的设计假设和需要核验的清单，不能宣布已经推导出唯一正确方案。

复杂系统重构、成本模型、多方约束或需要正式假设账本时读取 references/decomposition-and-reconstruction.md；简单问题不额外加载。

## Skill Composition

- 关键“基础事实”依赖尚未验证的因果机制，且有竞争性解释/证伪需求时，才按需组合 reasoning/scientific-reasoning；当前 Skill 保留方案重建的主目标。
- 用户要求对关键成本、硬约束、法律或外部事实做多来源核验时，按需组合 research/deep-research；检索结果用于确认约束，不让研究取代重构。
- 用户同时明确要求一份独立科学报告和另一份独立重构方案时，视为两个主交付物，按 Runtime 主 Skill 冲突规则处理，不能偷换成可选组合。

## 真实性与停止边界

- 不把常识、权威说法、个人偏好或流行口号自动当作不可改变的事实；也不因某条规则来自惯例就认定它无价值。
- 不忽略物理极限、已知事实、安全、法律、伦理及不可接受的风险；法律等制度约束须注明辖区与时间，可能变化仍要遵守当前要求。
- 不能仅凭形式上“从底层推导”就声称具有科学证据、经济可行性或最优性。
- 用户只要分析时不自动改代码、创建 Issue、形成正式决策或进入实施；进入领域执行阶段后及时交还主 Skill。
