# 产品决策账本与收口

正式讨论、追加决定或检查就绪时读取。记录为 Markdown，可写入当前产品配置的载体；“推荐”始终保持建议身份，直到用户确认。

## 讨论面板

背景与目标、范围/非目标、来源索引、当前流程/能力、目标与差距、决策依赖、当前待决项、有效决定、延期、状态。多步或跨角色行为用 Mermaid；当前图只包含事实，目标图只包含已确认规则。

## Q-xxx 问题节点

记录：问题、事实背景、前置依赖、影响范围、状态 unresolved/resolved/pruned/deferred/blocked、可回答条件。可自行调查的事实先查，不当作用户偏好问题。提供可执行选项、代价、推荐及依据；来源不足无法负责推荐时解释缺口。

默认先处理最高影响且前置已满足的问题。用户要求批量提问/作答时列出目前已知问题及条件依赖，回答后按依赖顺序记录；存在冲突只追问冲突节点，不重问整轮。未确认上游不得通过默认选择让下游分支“自动生效”。

## D-xxx 决定模板

```markdown
## D-xxx：决定主题
- 状态：已确认 / 部分确认 / 延期 / 否决 / 已被替代
- 对应 Q-xxx 与用户选择：
- 决定内容、适用范围和边界：
- 理由与证据：用户给出的理由与分析判断分开，不伪造用户动机。
- 否决/延期方案及原因：仅记录实际选择能支持的内容。
- 对现状、目标、交接和验收的影响：
- 仍未决：
- depends_on：
- supersedes：
```

重大决定独立记录。新决定替代旧决定时保留旧记录、标明替代关系；正文反映当前有效内容。不能静默改写历史。写后核对评论、面板、依赖和图一致，写入失败不能视为已保存。

## 状态与授权

- `discussion_in_progress`：仍有有效关键待决节点或事实核验。
- `blocked`：必需事实/授权缺失，写明仅阻塞哪部分。
- `ready_for_product_conclusion`：范围清楚、关键决定齐全、来源和图文一致、无未解决高影响冲突，可整理产品结论。

就绪检查还包括：用户的入口/动作/成功结果/失败恢复、权限与非目标、不适用分支理由、验收可推导性。空待决表不等于已经完整检查。

没有明确创建授权时只报告就绪状态，不自动创建产品/开发结论，不关闭讨论、不进入开发。用户明确要求跳过独立结论并开发时按共享交接规则记录授权，不把讨论已确认当作代码已经实现。
